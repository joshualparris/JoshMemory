## Narromine Visual QA Agent — five-stage pipeline

1. **Launch pinned baseline and candidate:** same build, same app source except intended changes, clean browser profiles, no external Google Street View calls.
2. **Replay identical route:** real browser WebGL, same desktop/Android sized device settings, deterministic simulation time, camera path, lighting, weather; capture actual rendered frames and record video.
3. **Measure:** spatial registration, frame-difference/temporal flicker statistics, frame times, shader and render-layer ablations; flag missing/unaligned/too-few frames as unverified.
4. **Diagnose, fix, repeat:** compare evidence, isolate exact cause, implement only claimed feature-owned fix, rerun unchanged test route; review code and visual/physical behaviour.
5. **Publish evidence:** source SHA and build manifest, screenshots and video, JSON/CSV report, explicit state (`improved`, `unchanged`, `regressed`, `unverified`), browser/device settings, defects, CI and actual deployed SHA when available.

## Mandatory acceptance / honesty rules

- The comparison **must not** conflate historical pre-patch `main` with unrelated new changes. Test #408 using a synthetic baseline generated from the **same source commit except the shader diff**, or compare branch head against its exact parent if only intended patch is present. Log precise code-source fingerprints.
- Use **real browser images** captured from `#scene` with WebGL enabled, plus executable metadata. A generated mock, screenshots of a blank canvas, source-only assertions, and green CI do not qualify.
- Render route time progression is controlled; avoid animation jitter and unrelated NPC/weather/lighting changes. Pinned deterministic camera waypoints and frame times are preferable to a manual or unrepeatable walk for the first visual comparison.
- Avoid external panorama/API calls and third-party imagery in public artifacts; don't commit credentials or large videos to git. Put generated media under ignored test-results and upload via workflow artifacts with limited retention.
- Compare each mode at identical pixel dimensions; if browser/OS/GPU differs or either branch cannot render, report `unverified`. Never call a regression green when a comparison wasn't run.
- Never weaken collision, geometry, privacy, licensing or real-world evidence standards to make the video pass. Keep findings distinct: shader shimmer, true z-fighting, shadow flicker, normal motion and road collision.
- Verify Node/build/privacy and CI, then actual browser result, then merged main and deployed source SHA. Each is a distinct acceptance level.
