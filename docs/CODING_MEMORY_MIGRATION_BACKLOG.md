## Intentionally excluded from cloud migration

These are not migration gaps:

- raw ChatGPT/Codex transcripts;
- full historical SQLite databases;
- personal health exports or health database contents;
- private family/finance/life memory unrelated to coding;
- passwords, API keys, tokens, cookies or other credentials;
- arbitrary local files/source trees already authoritative in Git repositories.

The reconstructed JSONL source files remain evidence/source material rather than being treated as current truth. Cloud memory stores compact redacted continuity and provenance references instead of a transcript dump.

## Unknown by design

Where the recovered corpus did not establish a canonical repository, deployment, current branch/HEAD or completion result, the migration records that state as `UNKNOWN`/historical rather than guessing. Examples include IncreaseHRV's canonical repo, some early game prototypes, DubboSDR's current state and several old Mac/Windows app variants.

A fresh agent must resolve those unknowns using live Git/API/machine evidence.

## Completion rule

A future agent should **not restart a 2026 coding-history migration** merely because raw transcripts are not present in GitHub cloud storage.

Start with:

1. `resume` / `resume_brief` for the target project;
2. `JoshCoding2026` and the recovered project catalogue for aliases/portfolio context;
3. `docs/CODING_2026_MASTER_HANDOFF.md` for the broad map;
4. live Git/CI/deployment/machine inspection for present truth;
5. historical search/source material only when compact memory is insufficient.
