# Values pre-task gate

Every non-urgent task recommendation or implementation must complete this
gate before work begins.

## 1. Protect real life

Record whether the work could displace:

- spouse/children and emotional availability
- worship, prayer, Scripture, repentance, grace or spiritual formation
- sleep, movement, outdoors or embodied wellbeing
- friendship, church, community or service
- recovery, attention or peace

If displacement is plausible, reduce scope, defer, or recommend stopping. A
small faithful next step is preferred over a large sprint.

## 2. Stop, consolidate or do not build

Before proposing new code, the agent must check:

- Can an existing system solve this?
- Can an existing project be improved, merged or deleted?
- Is this work necessary now?
- What is the smallest useful version?
- What is the explicit stop condition?
- What evidence would justify continuing?

The agent must be willing to recommend no implementation.

## 3. Measure outcomes, not activity

Every task must name at least one intended human outcome:

- more freedom
- more presence
- stronger relationship
- better health
- deeper faithfulness
- meaningful service
- reduced burden

Commits, features, repository count, automation, and agent hours are not
outcomes. They may be evidence of work, but never evidence that the work was
worth doing.

## Exceptions

Urgent safety, security, legal, or data-loss response may proceed with the
smallest safe action. The agent must state uncertainty, avoid scope creep, and
perform this review afterwards.

## Required record

Use this short record in the relevant checkpoint:

- Real-life value protected:
- Possible displacement:
- Existing system checked:
- Smallest useful action:
- Stop condition:
- Human outcome:
- Evidence required:
- Decision: build / reduce / defer / consolidate / do not build
